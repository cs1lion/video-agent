# 故事板功能研究报告（2026-09-05）

> **研究输入**：`“故事板”设计思路.txt`（三层模型：固定设定 / 可变状态 / 摄影表达；前置条件—动作—结果；双轨校验）+ 全部 doc/ 与服务端源码（不含 e2e 产物细节）+ 行业前沿检索。
> **标记约定**：凡标注 **【行业补充】** 的条目，为检索行业前沿后新增的观点/风险/方案，非原始设计思路中已有内容。
> **结论边界**：本文只做研究与排期，不改代码。所有"现状"均指 2026-09-05 代码实读结果（服务端 285 测试基线）。

## 0. 结论速览

| 问题 | 结论 | 依据 |
|---|---|---|
| 故事板开发是否可行 | **可行，且是"补中间层"而非"重建管线"**。三层模型中项目已有第 1 层（design-bible 实体）和第 3 层（prompts/transitions），缺的只有第 2 层"可变状态" | §2、§3 |
| 落地兼容性 | **高兼容**：新增 `storyboard.json` 中间产物 + 既有 stage 扩展字段，纯增量、向后兼容旧 run（缺字段兜底）。不需要动配额/调度/混音链 | §3.1 |
| 发挥预设作用 | **是**：CoCreationSpace 的 characters/scenes 与 design-bible 的 CH01/PR01/SC01 编号实体正是"固定设定层"的现成载体，故事板把它从"prompt 注入文本"升格为"逐镜结构化引用" | §3.2 |
| 解决的问题 | 跨镜人物一致性（G3 人物轴 55 分的根因之一是逐镜重描述）、道具换手、空间瞬移、QA 只能事后修不能事前防、reshot instruction 缺少世界状态依据 | §3.3 |
| 阻碍 | ①视频模型对结束状态的遵守是概率性的；②双轨校验烧配额（2.5-flash 2RPM/40-90s）；③QA 前缀遵循概率性已实证；④闸门交互成本增加；⑤多人物对话受"一镜一主语音"硬约束 | §3.4 |
| 声音同步 | **部分能解决**：对话时间轴（wordTimestamps 已在 schema，ROADMAP N1 排期中）故事板天然承接；多人物对话在现有模型约束下只能"统筹拆镜+声桥"，原生多说话人生成属模型上限；物品/场景声音目前几乎为零，可用"声音事件层 + V2A 生成"补齐 | §4 |

**一句话**：故事板 = 把项目里散落的"资产编号 + 逐镜 prompt + QA 事后闭环"折叠成一个**带状态演进的镜头序列**，用结构化状态把质量闭环从"发现问题→修画面"提前到"计划阶段就拦截矛盾"。声音侧则把当前"音频驱动单镜口型"升级为"全片声音事件时间轴"。

## 1. 现状盘点：故事板三层模型 vs 现有管线资产

| 故事板层（设计思路.txt） | 项目现有对应物 | 覆盖度 | 差距 |
|---|---|---|---|
| 第一层 · 固定设定（人物/道具/场景：唯一编号、参考图、外观） | `design-bible.json`（DesignEntity：character/prop/scene，编号 CH01/PR01/SC01，design-*.png 概念图）+ CoCreationSpace characters/scenes + keyframes 参考板 | ★★★★☆ | 缺"逐镜引用"结构（现在靠 prompt 文本复述）；道具缺"状态描述维度"（内容物多少、完整程度） |
| 第二层 · 可变状态（位置/朝向/持有/情绪/门开关） | **无**。ScriptShot 只有 visual 一句英文画面描述 | ☆ | **核心缺口**：状态散落在 prompt 自然语言里，无结构、无校验、无传承 |
| 第三层 · 摄影表达（景别/机位/运镜/时长/衔接） | `prompts.json`（逐镜英文 prompt）+ durationSec + motionIntensity + transitions.json（cut/fade + sfxType，EDL 转场预算 1/3） | ★★★☆☆ | 缺镜头间显式"关系字段"（连续动作/时间省略/声桥）；景别机位在 prompt 里但不可结构化检查 |
| 前置条件—动作—结果 | 无（最接近的是 QA 的 category 结构化：人物/物理/文字/字幕） | ☆ | 新增 |
| 双轨（计划状态 vs 实际画面） | QA 抽帧（qa-SH0x.jpg / -late.jpg）+ consistency.ts 跨镜一致性 + 自动闭环 selectAutoRepairTargets | ★★☆☆☆ | 已有"事后比对"骨架，但比对对象是"缺陷"不是"计划状态"；reshot instruction（画面设计前 120 字+reason）不含世界状态 |
| 声音 | audioMode 三态 + dialogue（TTS 词级时间戳字段已定义未实施）+ pausesSec + transitions sfxType + BGM 和弦合成 + DME 混音 | ★★☆☆☆ | 对白时间轴、环境声、物品音效、声桥（J/L-cut）均为空白 |

**关键判断**：故事板不是新管线，而是在 `01-script`（剧本）与 `04-prompts`（分镜提示词）之间插入一个 **storyboard 产物 + 状态校验器**，并让下游三个消费点（prompts 注入、reshot instruction、QA 状态轴）读它。

## 2. 问题一：可行性

### 2.1 结构可行性 —— 高
- 项目惯例是"LLM 产物 → normalize/sanitize → 落盘 JSON → 下游只读"（pipeline 七阶段每阶段如此）。storyboard.json 完全复用此模式：`stageStoryboard`（或 script 阶段扩展输出）→ 落盘 → prompts/keyframes/QA 消费。
- 状态机校验器适合做成**纯函数 + 契约测试**（先例：`selectAutoRepairTargets`、quota 守恒锁、ffmpeg-mix 时间轴锁）——这是项目最擅长的确定性验证形态，不需要新基础设施。

### 2.2 生成可行性 —— 中，取决于"遵守率"
- LLM 侧：让 script 阶段输出 前置条件/动作/结束状态/镜头关系 属于结构化 JSON 生成，与现有 script 输出难度同级，**低风险**。
- 视频模型侧：设计思路已指出"不能因为文本写了右手就默认视频正确"。项目实测（QA 前缀概率性、人物轴方差、跟读乱语）反复证明 **LLM/视频模型遵守都是概率性的**。所以可行性的真正考验在第 2.3。

### 2.3 验证可行性 —— 用现有 QA 帧骨架，不违反"不做清单"
- ROADMAP 不做清单有"读视频模型进管线"。双轨校验**不需要**读视频：复用 export 阶段已有的 QA 抽帧（每镜首尾帧 qa-SH0x.jpg）+ 一次视觉 LLM 调用做"计划状态 vs 实际画面"比对——与 consistency.ts 的 640px 压缩/指纹缓存基建完全同构。
- 【行业补充】**状态可观察性设计**：遮挡问题（设计思路 §五已提到"杯子被挡住≠消失"）在行业里被当作**镜头设计约束**而非验证难题——编剧阶段就要求"每个结束状态必须在尾帧可见或显式标注时间省略"。建议把"结束状态可观察"写成 storyboard 校验器的硬规则：不可观察的状态标记 `unobservable: true`，校验器按"未观察 = 保持"处理，不计入冲突。这比试图从遮挡画面推断状态便宜得多。

**结论**：可行。风险集中在"视频模型遵守率"这一模型上限上，用"计划状态置信度 + 有界重生成（attempt 预算）+ 状态差异透明呈现给用户"兜底，而不是追求零冲突。

## 3. 问题二：兼容性、预设作用、解决的问题与阻碍

### 3.1 兼容性清单（改动面盘点）

| 层 | 改动 | 类型 | 兼容风险 |
|---|---|---|---|
| `prompts.ts` 类型 | ScriptShot 增加可选字段（precondition/action/endState/relations/soundCues）或新增 StoryboardDoc | 增量 | 低（旧 run 缺字段兜底，项目有成熟先例：audioMode 缺省=narration、design-bible 旧 run 兜底 null） |
| script 阶段 | prompt 模板增加状态字段输出要求 | prompt 变更 | **生产行为变更**——按项目铁律需整批重验（G 批次回归） |
| 新增校验器 | 状态机纯函数（默认保持/未知保留/冲突检测） | 新文件 | 零 |
| prompts 消费 | 注入"继承状态 + 结束状态"块 | prompt 变更 | 同上，需重验 |
| keyframes 参考板 | 已有参考板机制，增加道具/场景参考图按需选择 | 增量 | 低（模型输入能力按需选择，设计思路 §五已预告） |
| QA | 新增"状态轴"或并入现有人物/物理轴 reason | prompt 变更 | 中：QA 前缀概率性会传导到 auto-repair 命中率 |
| reshot/retts | instruction 组装时带上"该镜结束状态 + 上一镜结束状态" | 增量 | 低，且直接改善现有闭环 |
| UI | StoryboardStage 从"提示词表"升级为三栏（资产/镜头卡/状态差异） | 前端 | 零后端风险 |
| 配额/调度/混音链 | **不动** | — | 零 |

**判断：落地形态是"script 阶段扩展 + 一个新校验器 + 三个消费点"，不需要动项目的钱线（quota/guard/queue）和音频骨架。** 唯一的硬闸门是两条项目铁律：①改生产行为必须整批重验；②闸门优先于派发——storyboard 状态确认应成为现有四道闸门之外的第 5 个确认点（或并入设计/关键帧闸门，避免确认疲劳）。

### 3.2 预设（CoCreationSpace / design-bible）能否发挥作用 —— 能，且是双向增益
- 现状痛点：coSpaceBlock 是"prompt 文本注入"，人物/场景设定在逐镜 prompt 里靠自然语言复述，没有编号引用（设计思路 §二核心诉求："小林和红杯在所有镜头里引用同一资产"）。
- 故事板落地后：design-bible 实体（CH01/PR01/SC01 + 概念图）成为镜头卡的**结构化引用**，镜头卡写 `characterId: "CH01"` 而不是重描一遍外貌；外观锚点注入（stages/prompts.ts 已有 designDoc 注入逻辑）从"全量注入"变为"按镜引用"。
- 【行业补充】**这正是行业主流做法**：LTX Studio 的 character/world bible → shot 级引用、Runway Gen-4 References（实体参考图跨镜复用）、VideoDirectorGPT（学术先例，剧本阶段产出实体清单驱动多镜一致性）走的都是"实体库 + 镜头引用"路线。项目的 design-bible 路线与业界收敛方向一致，故事板是让它发挥全部价值的关键一环。

### 3.3 解决的问题（对应已知实证痛点）

| 现状问题（实证来源） | 故事板如何解 |
|---|---|
| 跨镜人物一致性是最低分轴（G3 人物轴 55、G7 70；第五轮跑批专项根治） | 人物外观逐镜引用资产 + 服装/发型进入"固定设定"，不再逐镜重述产生漂移机会 |
| 道具乱入/换手（auto-repair 测试真实案例：羽毛球拍乱入） | 道具持有关系是第二层状态的一等字段，计划阶段即校验 |
| 空间瞬移、动作断裂（设计思路 §一：镜头一到镜头二缺"走到门口"） | 前置条件—动作—结果链 + 显式"时间省略"标注，计划阶段拦截 |
| QA 只能事后修（warn 前缀概率性导致漏选） | 冲突在生成前由确定性校验器拦截（不依赖 LLM 遵守）；QA 从"发现缺陷"升级为"核对计划状态"，命中标准客观化 |
| reshot instruction 弱（画面设计前 120 字 + reason，无世界状态） | instruction 携带"结束状态差"，重拍目标从"修掉问题的画面"变为"恢复计划状态" |
| 字幕/口型错位根因（N1 未实施） | 故事板声音层给出台词时间轴的挂载点（§4.1） |

### 3.4 阻碍清单（按严重度排序）

1. **视频模型遵守概率性**（模型上限）：结束状态写了也可能不照做。对策：双轨校验 + 有界重生成（每镜 attempt 预算，复用 MAX_RESHOT_PER_SHOT 幂等锁模式）+ 状态差异如实呈现。**不要为"状态轴分数"调阈值**——项目对人物轴已有同样纪律。
2. **配额与 RPM**（2.5-flash 2RPM、40-90s/镜）：双轨校验增加一次视觉调用/镜（便宜），但"冲突→重生成"是整镜重烧。对策：冲突只在 fail 级（持有关系错、动作矛盾）才自动重拍，观感级进人工确认；闭环预算沿用 ≤2 镜/轮。
3. **QA 前缀遵循概率性**（已实证）：状态轴 reason 若也依赖前缀路由会继承此病。对策：状态轴判定**不依赖** reason 前缀，比对对象是 storyboard.json 的结构化字段（确定性输入），这恰是相对现有 QA 的结构性改进。
4. **prompt 模板变更 = 整批重验成本**：script/prompts/QA 三处模板都要动。对策：分两批落地（先 prompts 消费侧小批重验，再 script 生成侧整批回归），批次排进 e2e 工具链（run-e2e --only 单片先行）。
5. **交互成本**：新增状态确认点 vs 现有四道闸门。对策：第一版按设计思路 §六"修改前的动作 → 标受影响镜头 → 用户确认"，不自动改后续剧情；状态差异用"开始态/结束态 diff 卡"呈现，不要求用户逐字段审。
6. 【行业补充】**重生成不收敛风险**：改状态 → 重拍 → 新画面引入新偏差 → 再拍，行业实测中"连续重拍同一镜"的收益递减明显。必须设置"状态差异接受度"出口（如：持杯手错但不影响后续镜头理解 → 接受并**更新计划状态**，让后续镜头继承实际状态而不是硬拗重拍）。这要求 storyboard.json 支持"实际状态回写"（计划态 vs 实际态双份），是双轨机制的完整形态。
7. 【行业补充】**schema 的模型无关性**：Veo 3 / Sora 2 已走通"音画同生"路线（对话口型、环境声一次生成，Veo 3.1 另有 ingredients 参考实体与首尾帧控制）。项目当前 reference 路线（先 TTS 后对口型）与之是两条技术路线。故事板 schema 应把"结束状态/声音事件"设计为**模型无关字段**，未来切换/混用原生音画模型时，镜头卡仍是唯一事实源——不需要预研迁移，只需要不把字段绑死在 reference 模式的实现细节上。

## 4. 问题三：声音同步专项

### 4.1 人物对话时间轴 ↔ 画面对齐 —— 故事板能接住，且已有地基

现状：ShotDialogue 已定义 `wordTimestamps`（词级时间戳，生成链路回写）与 `pausesSec`（停顿=表演），A4b 已实现"以音频反推镜长"（ceil(audioDur) 钳 4-12s），dubOver 兜底保证声音正确性优先于口型。ROADMAP N1（词级时间戳字幕）已排期近期。

故事板的角色：把"声音时间轴"从**每镜私有**提升为**全片公共时间轴**——
- 镜头卡新增 `soundCues`（台词在镜内起点 offset、语音就绪后与画面的对齐意图）；
- N1 落地后，词级时间戳可直接写回镜头卡，export 的字幕三重收束（≤镜长-0.3/≤下镜切点-0.1/≤人声+0.8s）从"估算收束"升级为"实测对齐"；
- 跨镜对齐由"镜头衔接关系字段"承载（见 4.2 的声桥）。

**判断：能解决，且主要是工程活（N1 是前置依赖），无模型风险。**

### 4.2 多人物对话统筹 —— 现有约束下"统筹拆镜 + 声桥"，原生多说话人属模型上限

现状硬约束：D1 `enforceSingleSpeaker` 前置闸——多角色对白必须拆镜（audios 多条互相干扰，2.5-flash reference 模式实测约束）。项目已实证"密集对话"是重灾区（doc/scripts/dense-dialogues 五套压力剧本、历史踩坑补遗两轮）。

故事板能做的（不违反硬约束）：
1. **对白轮次表（turn-taking）**：故事板第二层新增"谁在何时说话"序列，script 阶段按轮次自动拆镜并保证衔接镜头的动作状态（说话人 A 说完 → B 的反应镜头前置条件"B 在听、朝向 A"）——把 D1 从"事后拦截降级旁白"升级为"计划阶段就按单说话人拆好"，消除用户写完剧本才发现要拆镜的返工（audio-mode.ts 注释里点名的痛点）。
2. **声桥（J-cut/L-cut）进故事板**：设计思路 §四的"声音关系"字段（上一镜声音延续/下一镜声音预进）落到 export 混音层是纯 ffmpeg 语义（对白总线提前/延后进点），与 A3 已有的"台词镜进入前静音"时间轴锁同族。**注意**：一镜一主语音约束下，"声音预进"只能预进下一镜已生成的整段语音（在切点前 0.3-0.8s 进入），不能跨镜拼接半句话——TTS 是逐镜生成的，跨镜拼接会破坏词级时间戳与口型对齐。这是结构与模型的双重边界，不是故事板能绕开的。
3. 【行业补充】**原生多说话人生成是行业已解但本项目不可用的问题**：MultiTalk（NeurIPS 2025，音频驱动多人对话视频生成，单/双/多人由位置编码控制，支持跨镜一致性）与 Veo 3 的多角色对话已验证该能力可模型化；但本项目绑定 agnes 2.5-flash reference 模式，**短期内多人同镜对话属于"记录不硬修"的模型上限**（与 ROADMAP 对模型上限类问题的处置原则一致）。故事板的价值在于：即使生成侧继续拆镜，**统筹层（谁何时说、如何衔接、如何运镜反应）已是正确且可编辑的**——未来接入支持多说话人的模型时，只需换生成适配器，统筹层原样复用。

**判断：能解决"统筹"，不能解决"同镜多人生成"（模型上限）。对多人物对话实际较少见的作品结构，统筹层收益已覆盖绝大多数场景。**

### 4.3 物品与场景声音（Foley/环境声）—— 现状空白，故事板 + V2A 是当前最优组合

现状：全片声音只有四类——TTS 语音、BGM（和弦合成）、转场 sfxType（whoosh，全片限 2 处）、DME 混音链。**物品音效（敲门、倒水、雨声）与环境底噪完全没有生产路径**，成片声音远未饱和。

【行业补充】行业前沿是 **V2A（video-to-audio）**：MMAudio（CVPR 2025，音视频联合训练，从视频反推同步音效）、Kling-Foley（快手，视频转音频 DiT，立体声）、HunyuanVideo-Foley（腾讯）等已开源/产品化，生成 4-10s 与画面事件同步的音效+环境声。这与故事板的配合方式是**声明式**的：
- 故事板声音层写"事件意图"（soundCues：`{t: 2.0, kind: "object", desc: "陶瓷杯放上木桌"}`、`{kind: "ambient", desc: "雨夜便利店荧光灯嗡鸣"}`）；
- 生成侧两条路：a) V2A 模型从成片片段直接反推（同步性最好，无需故事板也能生成，但风格不可控）；b) 按故事板 soundCues 用音效库检索/V2A 定向生成再混音（可控性最好）。
- 建议本项目路线：**第一版只做"声音事件层"数据结构 + 音效库检索混音**（ffmpeg amix 进现有 DME 总线，工程风险低）；V2A 模型接入作为 P6 spike（不动主线，先验证同步性与质量）。理由：V2A 引入新的模型依赖与长任务类型，而音效库方案与现有 quota/guard 体系零耦合。

**判断：故事板本身不生成声音，但它提供了"声音事件与画面时间轴对齐"的唯一合适挂载点——没有声音事件层，V2A/音效库永远是后期贴片；有了它，才谈得上"统筹"。**

## 5. 原始问题之外、研究后发现需要考虑的问题（均为【行业补充】）

1. **状态可观察性是镜头设计约束，不是验证难题**（§2.3 已述）：剧本阶段就要求结束状态尾帧可见，或显式标 `unobservable`，校验器按"未观察=保持"处理。否则状态校验会被遮挡问题拖进不可判定的泥潭。
2. **计划态与实际态双轨要支持"接受现实"**：重生成不收敛时，把实际观察到的状态**回写**为新的计划状态、让后续镜头继承——这是双轨机制的完整闭环，也是避免"为忠实于一个错误计划反复烧配额"的出口（行业对 AI 重拍收益递减的普遍经验）。
3. **prompt 注入预算**：storyboard 的状态块会加大逐镜 prompt（现状 bible 已全量 JSON 注入）。行业做法是"按镜引用裁剪"——每镜只注入该镜出现实体的状态，实体出场表（哪些实体在本镜出现）应成为 storyboard 字段之一。
4. **评估体系要同步扩展**：项目最值钱的是 Evals 文化（"评估的评估"）。故事板需要：状态机校验器契约测试（计划态冲突检测的变异验证）、e2e 断言（"道具持有关系全片无计划冲突"）、以及一个"计划 vs 实际"命中率指标（可观测，先不做 gate——同 QA 分数不做 gate 的既有决策一致）。
5. **工业格式出口**：镜头关系 + 声音事件时间轴天然接近剪辑交换标准（OTIO/EDL）。transitions.json 已是半个 EDL；把 soundCues/关系字段也按时间轴语义设计，未来可导出给专业剪辑/声音软件，这决定 schema 设计时要用绝对时间轴思维（镜头起点 offset）而不是只有镜内相对时间。
6. **演示与叙事价值**：三栏故事板 UI（资产/镜头卡/状态 diff）是面试动线里"结构化状态机 + 确定性校验"的最佳可视化载体，比现有提示词表更能讲清项目的方法论差异。
7. **版权与音色合规边界不变**：声音事件层若未来接 V2A/音效库，注意音效素材授权与 TTS 音色条款同一等级的合规检查（项目已在音色复刻上有"不做"先例）。

## 7. 建议的不做清单（维持纪律）

| 不做 | 理由 |
|---|---|
| 同镜多说话人生成（MultiTalk 类自部署 / 换模型） | 模型上限 + 依赖重；统筹层已覆盖收益，记录不硬修 |
| 故事板自动改写后续剧情（dirty 镜头自动重生成） | 违背设计思路"用户确认制"；配额失控风险；UI 只标记不执行 |
| 状态轴分数作为 gate | 同 QA 分数不做 gate 的既有决策（同帧复评浮动） |
| 读视频模型进管线做状态校验 | 维持 director-agent 不做清单；复用 QA 抽帧即可 |
| 第一版就接 V2A 模型依赖 | 新模型依赖 + 长任务类型；P7 spike 先行验证 |
| 屏蔽"不许越轴"为绝对规则 | 设计思路已定：可有意越轴，但须有可理解的过渡；写成软警告 |
