## 2. P0 · schema 定稿（Step 1-4，约 0.5 天）

### P0-S1 · server 类型定义（prompts.ts 追加）

新增类型（全部 export，本阶段**无任何消费方**，仅为 P2/P3 预留）：

```ts
/** 故事板镜头卡（P0 schema 定稿；P2 起由 script 阶段生成，P3 起被 prompts/QA/reshot 消费） */
export interface StoryboardState {
  /** 实体引用：值必须是 design-bible 的实体 id（CH01/PR01/SC01），不重述外观 */
  characterIds?: string[];
  propIds?: string[];
  sceneIds?: string[];
  /** 固定属性在本镜的变化（如服装更换）；缺省 = 沿用资产设定 */
  appearanceOverrides?: Record<string, string>;
  /** 动态状态：位置 / 朝向 / 持有关系 / 姿势 / 情绪；缺省 = 继承上一镜结束状态（默认保持） */
  position?: string;
  facing?: string;
  holding?: { entityId: string; hand: "left" | "right" | "both" }[];
  posture?: string;
  mood?: string;
  /** 本镜是否可观察到该状态（遮挡/出画）：true = 校验器按「未观察=保持」处理，不计冲突 */
  unobservable?: boolean;
}

export interface StoryboardShotCard {
  shotId: string;
  /** 前置条件：进入本镜时的世界状态（必须等于上一镜结束状态或显式声明时间省略） */
  precondition: StoryboardState;
  /** 动作：本镜发生的改变 */
  action: string;
  /** 结果：本镜结束时的世界状态 */
  endState: StoryboardState;
  /** 镜头关系：与上一镜怎么接（时间/空间/动作/声音四轴） */
  relation?: {
    time: "continuous" | "overlap" | "ellipsis" | "flashback";
    space: "same-location" | "follow" | "new-location";
    actionLink?: string;
    /** 声桥：上一镜声音延续 / 本镜声音预进（P6b 消费，schema 先行） */
    sound: "carry-over" | "pre-lap" | "none";
  };
  /** 声音事件（P6a 消费）：t 为镜内相对秒；绝对时间轴由镜长累加推导（OTIO 兼容思维） */
  soundCues?: { t: number; kind: "dialogue" | "object" | "ambient" | "sfx"; desc: string }[];
  /** 对白轮次（P2 turn-taking 拆镜依据；一镜一说话人约束不变，此字段管"谁何时说"统筹层） */
  dialogueTurn?: { speakerId: string; order: number };
  /** 双轨：计划态（生成前写）vs 实际态（P4 双轨校验后回写）；缺省 actualState = 未校验 */
  plan: { start: StoryboardState; end: StoryboardState };
  actualState?: { start: StoryboardState; end: StoryboardState };
}

export interface StoryboardDoc {
  version: number;
  shots: StoryboardShotCard[];
}
```

要点：
- 放在 `prompts.ts` 现有 `ScriptDoc` 之后（§script 类型区），不移动既有代码；
- 实体引用字段注释必须写明"值必须来自 design-bible 实体 id"——这是"资产引用而非重述"的 schema 强制位；
- `relation.time === "ellipsis"`（时间省略）与 `precondition` 的关系写进 TSDoc：省略时 precondition 允许偏离上一镜 endState，校验器据此豁免。

### P0-S3 · 语义注释

两条语义规则的 TSDoc 落位：
1. **默认保持**：`StoryboardState` 字段缺省 = 继承上一镜 `endState` 对应字段，不重置；

## 3. 字段语义表（评审用）

| 字段 | 层 | 语义 | 缺省行为 |
|---|---|---|---|
| characterIds/propIds/sceneIds | 固定设定 | 引用 design-bible 实体，禁止重述外观 | 继承出场表 |
| appearanceOverrides | 固定设定 | 本镜外观变化（换装等） | 沿用资产 |
| position/facing/holding/posture/mood | 可变状态 | 动态世界状态 | **默认保持**（继承上一镜 endState） |
| unobservable | 可变状态 | 本镜状态不可观察标记 | false |
| precondition/action/endState | 状态链 | 前置条件—动作—结果 | precondition 必须等于上一镜 endState（或 ellipsis 豁免） |
| relation（time/space/actionLink/sound） | 镜头关系 | 与上一镜怎么接 | time=continuous, sound=none |
| soundCues | 声音事件层 | 镜内相对时间的事件声明（P6a 消费） | 空 |
| dialogueTurn | 对白统筹 | 谁第几轮说（P2 拆镜依据） | 缺省非对白镜 |
| plan vs actualState | 双轨 | 计划态 vs 实际态（P4 回写） | actualState 缺省=未校验 |

## 4. P1 · 状态机校验器（Step 5-6，约 1.5 天）

### P1-S5 · `storyboard-state.ts` 纯函数

函数形态（先例：`selectAutoRepairTargets` 导出纯函数 + 契约测试锁定的模式）：

```ts
/** 六条规则的结构化输出：每条冲突带规则 id 与涉事镜头，供 UI dirty 标记与 P4 重拍分级复用 */
export interface StateConflict {
  rule: "holding" | "position" | "facing" | "precondition-link" | "relation-validity" | "soundcue-bounds";
  shotId: string;
  message: string;
}

export function validateStoryboard(
  doc: StoryboardDoc,
  entityIds: { characters: string[]; props: string[]; scenes: string[] },
): StateConflict[];
```

规则清单（实现顺序即评审顺序）：

| # | 规则 | 判定 | 冲突示例 |
|---|---|---|---|
| R1 | 默认保持 | 本镜 plan.start 缺省字段 = 上一镜 plan.end 对应字段；**校验器先做状态展开（继承折叠）再比对** | 镜2 声明 holding 红杯但未声明 镜1 endState 放下 → 折叠后冲突 |
| R2 | 未观察保持 | `unobservable: true` 的镜：start 与上一镜 endState 不比对；actualState（若有）与 plan 比对跳过 | 杯子被挡住 ≠ 冲突 |
| R3 | 持有关系 | holding 的 entityId 必须在 propIds/出场实体中；同一实体不能同时被两手持不同镜声明矛盾；hand 枚举合法性 | 左手拿杯 又 右手拿杯 |
| R4 | 位置/朝向连续性 | 非 ellipsis 镜之间 position/facing 突变且 action 未声明移动/转身 → 冲突 | 人在桌旁 → 人在走廊，中间无迁移镜且无 ellipsis |
| R5 | 镜头关系合法性 | relation 引用 shotId 必须存在；`ellipsis` 必须显式（隐式时间跳变 = R4 冲突）；flashback 后应有回到主线的关系声明 | 关系字段指向不存在的镜头 |
| R6 | soundCues 边界 | t ∈ [0, 该镜 durationSec]；kind=dialogue 必须有对应 dialogueTurn | 音效点超出镜长 |

实现纪律：
- **纯函数**：不读文件、不调 LLM、不依赖全局状态；`durationSec` 从入参传入（与 script 解耦，本阶段 script 尚无状态字段）；
- 输入用 P0 定稿的 `StoryboardDoc` + 实体 id 清单；fixture 可手写，不依赖管线产物；
- 校验是**计划态自检**（R1-R6 都作用于 plan），actualState 比对是 P4 的活，本阶段只留类型位。

## 9. P2/P3 接口预留说明

- `validateStoryboard` 的输出（`StateConflict[]`）即 P2 script 扩展后的"计划阶段拦截器"：P2 在 script 产物落盘前调用，fail 级冲突带强化反馈重写（复用对白密度守卫的"带反馈重写一次"模式）；
- `StoryboardShotCard.dialogueTurn` 即 P2 turn-taking 自动拆镜的数据源：script prompt 输出轮次表 → 拆镜逻辑按单说话人切分并生成衔接镜头的 precondition；
- `relation.sound` 字段 P6b 消费；`soundCues` P6a 消费——schema 一次定稿，下游分期接线，不做字段迁移。

### P3 · 提示词消费规格（四段式示例，schema 评审的具象参照）

**双通道前提**：视觉继承（人物脸/道具样式/场景布局）靠 keyframe + design-bible 参考图；
**语义继承**（持有关系/门开关/朝向）靠文本锚定。状态同步在 prompt 里翻译成三个位置：
开头"从哪个状态接着演"（衔接锚点）、结尾"演到什么状态为止"（结束状态锚点）+ "不许发生什么"（负向护栏）。
**默认保持在文本层的体现：没被事件改变的状态一个字都不写**——写了反而给模型自由发挥的口子。

以设计思路的咖啡杯 SH02（手部特写，接 SH01 拿杯）为例：

```
【衔接锚点 · 上一镜 endState，只写不改的】
Continuation from previous shot: Xiaolin holds the red enamel cup in his
RIGHT hand (just lifted from the desk), his left hand is free, he stands
beside the desk facing east, the door behind him is closed.

【本镜动作 · action】
He steadies the cup in his right hand and reaches with his LEFT hand
toward the door handle.

【结束状态锚点 · endState】
By the end of this shot: the cup remains in his RIGHT hand, his left hand
is on the door handle, the door is still closed.

【负向护栏 · 把最怕的同步事故写成禁令】
Continuity anchors: the cup must NOT change hands during this shot; no
new props enter frame; handle orientation matches the attached prop
reference. Strictly avoid: morphing objects, extra fingers...
```

**时间省略（ellipsis）的措辞**——同时服务模型理解与 R4 豁免（同一事实的两种形态）：

```
Moments later (time ellipsis): Xiaolin has crossed the corridor to the
building entrance, cup still in his right hand, door now open behind him.
```

**P4 重拍指令（双轨闭环后的形态）**——从"修 QA 说的毛病"变成"恢复计划状态 + 指明偏差"：

```
Reshot SH02: the previous take ended with the cup in his LEFT hand
(planned: RIGHT hand, inherited by SH03). Regenerate this shot keeping
the cup in the RIGHT hand for the entire duration; end state unchanged:
left hand on the door handle, door closed.
```

**诚实边界**：prompt 是意图不是保证——对状态指令的遵守是概率性的（与 QA 前缀遵循同理）。
提示词层的目标是**把遵守率推高 + 把偏差变得可检查**（双轨校验 / unobservable / 实际态回写兜底），
同构先例：dubOver 的"文本承诺不了声音正确性，就用关卡 + 兜底"。
