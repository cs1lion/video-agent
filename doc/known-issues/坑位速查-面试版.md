## A. 部署 / 运维（CloudBase 云托管）

| # | 坑 | 一句话 | 严重度 | 记录处 |
|---|---|---|---|---|
| A1 | 缺 workspace dist | 单容器部署必须随镜像带 **5 个** dist，少一个就 `ERR_MODULE_NOT_FOUND` 起不来 | P0 | 施工报告根因A |
| A2 | 云托管不注入 PORT | `--port 8080` 只是声明，容器里 `process.env.PORT` 为空 → 回退 8787 → 探针失败 | P0 | 施工报告根因B |
| A3 | `--force` 不跳过灰度交互 | 不带 stdin 会卡在 prompt 后 EOF 失败；用 `printf '\n' \|` 喂默认项 | P1 | deploy/README §3 |
| A4 | `--wait` 不可靠 | 提交后改用轮询 `detail`（OnlineVersionInfos 有条目=成功）+ `logs process` | P1 | deploy/README §3 |
| A5 | MinNum=0 缩零 | 冷启动 503 约 10–20s；对外发链接前必须**预热** | P1 | 本文 §预热协议 |
| A6 | 构建上下文污染 | OneDrive 的 node_modules/批次产物不能进包；staging 排除后单独补 5 dist + models.json | P1 | 施工报告 §构建上下文 |

### A1 详解：少一个 dist 就起不来
- **现象**：`deploy_failed`，日志 `ERR_MODULE_NOT_FOUND: .../packages/coding-agent/dist/index.js`。
- **根因**：`config.ts` 直接 import studio adapter 源码，解析到 4 个 workspace 包
  （`agent/ai/coding-agent/tui`）+ 传递依赖 `telemetry` = **共 5 个 dist**。
  `.dockerignore` 只放行 3 个。
- **解法**：`.dockerignore` 与 `Dockerfile` 各放行并 COPY 全部 5 个。
- **一句话**：monorepo 单容器部署的隐藏契约是「dist 清单」，它不由 `package.json` 声明、
  只在运行时暴露——**排查手段必须是查日志里的模块路径，而不是看依赖树**。

### A2 详解：平台不注入 PORT
- **现象**：构建成功、探针 `dial tcp :8080 connect: connection refused`。
- **根因**：`config.ts` 用 `process.env.PORT ?? 8787`，云托管**不向容器注入 PORT**。
- **解法**：Dockerfile 显式 `ENV PORT=8080`（控制台同名变量可覆盖）。
- **一句话**：PaaS 的"端口配置"是给**负载均衡**用的，不是给容器进程用的——
  进程该监听哪个端口，必须自己写死默认值。

### A5 详解：冷启动与**预热协议**（对外发链接前必做）
- **现象**：`MinNum=0` 时实例会缩零，缩零后首请求返回 **503**，约 10–20s 后恢复 200。
- **操作协议**（发链接给别人前）：
  1. **发消息前几分钟自己先访问一次**预热（`curl /api/health` + 首页各打一次）。
  2. 消息里**必须写明**：「首次打开需等 10 秒左右」。
  3. 更好：发完 **10 分钟内再点一次**保温（缩零窗口内续命）。
- **长期解法**：控制台 → 云托管 → 服务设置 → **实例数下限改为 1**（常驻）。
  CLI 3.8.1 无 update 子命令，只能控制台改。
- **一句话**：Serverless 缩零省钱的代价是**首请求可用性**——
  对外演示要么常驻实例，要么把预热写进流程，不能指望用户重试。

## B. 台词链路 / 音频驱动（核心业务）

| # | 坑 | 一句话 | 严重度 | 记录处 |
|---|---|---|---|---|
| B1 | reference 跟读内容层不可信 | 包络相关 0.78–0.91，但 ASR 字面重合仅 0.07–0.14——**模型在模仿节奏说乱语** | P0 | 台词链路根修报告 |
| B2 | 参考音频不能重编码 | 提交必须是原始 24kHz TTS；重编码 44.1k mp3 会让供应商读失败（0.568 → 0.072） | P0 | 同上 |
| B3 | 双网关 401 ≠ 失效 | key1/2 → apihub，key3/4 → api.agnes-ai.cn；A 网关 401 先换网关，持续才隔离 30min | P1 | MEMORY §3 |
| B4 | 一镜一主语音互斥 | `normalizeScript` 对 dialogue 镜清空 narrationZh/En | P1 | 同上 |
| B5 | 字幕锚定人声不是镜长 | 台词字幕 ≤ 人声时长 +0.8s；节奏用 `rawDurationSec`（垫尾静音不进镜长） | P1 | 同上 |
| B6 | 整片直审 | step-3.7-flash 可吃 base64 MP4（<128MB）整片审；content 空时去 reasoning 尾部捞 JSON | P1 | 同上 |

### B1 + B2：为什么这道防线是产品级决策
- **根因**：音频相似度指标（包络/梅尔）衡量的是**声学相似**，不是**语义正确**。
  模型可以完美模仿节奏和音色，说出完全不相干的话。
- **解法**：双关卡（`qa/audio-follow.ts` 包络 ≥0.7 + `qa/asr-check.ts` ASR 重合 ≥0.5），
  未过 → `dubOver`（保留口型画面、音轨换 TTS 原声）。
- **定案**：**声音正确性 > 口型同步**，这是定案不是遗留权衡。
- **一句话**：当你用一个"相似度"指标去验收一个"正确性"目标时，模型一定会找到
  **指标高但结果错**的解——**必须补一个语义级（ASR）的第二关卡**。

## C. 架构 / 状态管理

| # | 坑 | 一句话 | 严重度 | 记录处 |
|---|---|---|---|---|
| C1 | 配额与 Key 类型混为一谈 | `QUOTA_DAILY_SEC=0` 曾把企业版 RPM 2 误标 free 的 1，让 ReAct 代理**低估自身能力** | P0 | MEMORY §2 |
| C2 | 每 key 限流各自独立 | N key = N 池，总 RPM = 各池之和；唯一决策点 `stages/clips.ts: reserveShotQuota` | P0 | MEMORY §2 |
| C3 | SSE 双通道 | `pushEvent` 已不调 `persistRun`，团队消息只走 `event: ev`——前端不接就**完全不显示** | P1 | MEMORY §4 |
| C4 | zustand v5 useShallow | 必须从 `zustand/react/shallow` 导入；且**拦不住引用变化**——高频流要存独立字段 | P1 | 总文档 L119 |
| C5 | 闭包型 TDZ | TS 的 TS2448 与 Biome 都拦不住，**只有运行时行为测试能发现** | P0 | 总文档 L112 |

### C1：一个配置歧义如何污染 Agent 的自我认知
- **根因**：`config.ts` 把"有无时长配额"当作"Key 层级"的代理指标。限时免费期 `=0` 关掉配额，
  顺带把企业版 RPM 判定成免费版的 1。
- **后果**：ReAct 调度代理按错误的能力上限做并发决策——**它以为自己只有 1 RPM**。
- **解法**：新增 `VIDEO_AGENT_QUOTA_KEY_TYPE` 显式覆盖，默认推断 `enterprise`，
  配 5 条语义测试 + **变异验证**（人为塞回 bug 确认测试变红）。
- **一句话**：给 Agent 的**能力画像**必须是显式声明，不能从别的配置"推断"——
  推断错一度，Agent 的整条规划就保守一档。

### C5：类型检查拦不住的 bug，怎么保证不复发
- **根因**：TS2448（TDZ）对**闭包内**引用不生效；Biome 开
  `correctness/noInvalidUseBeforeDeclaration: error` 仍零告警（均已实测）。
- **解法**：此类重构必须配**行为测试**，并做**变异验证**——否则很可能写出空测试。
- **一句话**：静态分析的盲区要用**运行时行为测试**补，而测试本身要用**变异测试**验证它真的会红。

## F. LLM-as-judge 的假阳性

| # | 坑 | 一句话 | 严重度 | 记录处 |
