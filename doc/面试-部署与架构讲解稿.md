## 0. 一句话定位（电梯陈述，30 秒版）

> 我做了一个**多 Agent 协作的视频广告生成系统**：用户输入一句创意，系统用一条 8 阶段 DAG 流水线（编剧→美术→分镜→提示词→镜头→音频→导出），由 9 个扮演不同工种的角色（导演/编剧/美术/声音/剪辑/审片…）在「团队频道」里协作完成成片，端到端约 6 分钟。调度核心是**音频驱动 + ReAct 并发生成**，并针对视频模型 API 的 RPM 限速做了多 key 限流池优化。部署上从云托管切到自建云服务器，因为云托管体验版有 3000 点/月的额度天花板、耗尽即停服。

## 1. 系统架构

### 1.1 流水线（8 阶段 DAG → 收敛为 7 阶段）

```mermaid
flowchart LR
  U[用户创意<br/>logline] --> S[script 编剧]
  S --> V[visual 美术设定<br/>+ keyframes 关键帧]
  V --> P[prompts 逐镜提示词<br/>注入角色外貌锚点]
  P --> C[clips 镜头生成<br/>ReAct 并发调度]
  P --> A[audio 音频<br/>TTS 优先 / 对白驱动口型]
  C --> E[export 合成 + 字幕]
  A --> E
  E --> O[成片 videoUrl]
  D[导演对话<br/>planDirectorReply] -. 驱动/微调/重做 .-> S
  D -. .-> C
  D -. .-> A
```

阶段文件（均在 `pi/packages/video-agent-server/src/stages/`）：
`script.ts` · `visual.ts` / `visual-derive.ts` · `keyframes.ts` · `prompts.ts` · `clips.ts` · `audio.ts` / `dialogue-audio.ts` · `export.ts` / `export-subtitle.ts`

### 1.2 团队角色（9 个，激活 7 个）

类型定义在 `pipeline.ts:298`：`producer / writer / art / storyboard / tech / sound / editor / reviewer / director`。
团队频道事件模型在 `pipeline.ts:262`、角色枚举 `pipeline.ts:297`。

| 角色 | 职责 | 关键实现 |
|---|---|---|
| director 导演 | 接收用户指令、决定微调/重做、串联各阶段 | `planDirectorReply` + 对话驱动管线 |
| writer 编剧 | 把 logline 扩成逐镜剧本 | `stages/script.ts` + `coSpace.scriptIntent` |
| art 美术 | 角色卡 / 画风 bible | 外貌锚点注入 `pipeline.ts:2362` |
| storyboard 分镜 | 关键帧 | `stages/keyframes.ts` |
| tech 技术导演 | 镜头参数 / 资源 | — |
| sound 声音 | TTS 选角、对白驱动口型 | `audio-mode.ts` / `voice-cast.ts` |
| editor 剪辑 | 拼接 + 字幕 | `stages/export.ts` + `export-subtitle.ts` |
| reviewer 审片 | LLM-as-judge 一致性 / 整片审阅 | `consistency.ts` / `e2e/deep-review.mjs`（step-3.7-flash） |
| producer 制片主任 | 只读资源与进度，不碰创作 | `producer.ts:92`（角色契约） |

### 1.3 团队频道（多 Agent 协作的可视化载体）

- **SSE 双通道**（`server.ts:678` / `server.ts:682`）：状态级 `event: run` + 事件级 `event: ev` + `: ping` 心跳。
- 关键设计：`pushEvent` **不再调 `persistRun`**——团队消息只走 `ev` 通道（`pipeline.ts` 注释明确）。前端必须同时接 `run` 和 `ev`，漏接 `ev` 就完全看不到团队消息。
- Nginx 反代必须 `proxy_buffering off`，否则事件被攒住不推（实测公网 20s 内实时到达）。

## 2. 技术深度亮点（能抠代码的四块）

1. **音频驱动管线 / TTS 优先**
   `prompts.ts:21` 明确：`dialogue` 镜 = 角色对白驱动口型（**先 TTS → 托管音频 → 作为视频参考生成**，而非先出画面再配音）。这是「声音正确性 > 口型同步」定案的工程落地。
2. **台词守卫 D1**（`audio-mode.ts:51`）
   多角色对白每镜只能一条主语音，落盘前前置闸门强制拆镜，否则按旁白兜底——解决「一镜多声互相干扰」。
3. **跨镜一致性**（最强抓手）
   `pipeline.ts:2362` 把美术 bible 的角色外貌短语回填进逐镜 prompt（"Zhao (黑色短发…)"），解决 LLM 只写角色名不携带外貌导致视频模型换人。`consistency.ts` 再做审校模型预检（服装/发型/画风跳变）。
4. **多 key 限流池**（ReAct 并发生成不被限速打挂）
   每个 API key 独立 RPM（`QuotaLedger.pickPool()`），N key → N 池 → 总 RPM 为各池之和；唯一决策点 `stages/clips.ts` 的 `reserveShotQuota`（clips/reshot/retts 三路径共用）。实测推翻官方「按 key 类型共享」的假设。

## 3. 部署架构：云托管 vs 自建 CVM

| 维度 | 云托管 CloudBase（旧） | 自建 CVM 49.233.207.18（现） |
|---|---|---|
| 形态 | 单容器同源（Express 同服务 /api + UI 静态） | Ubuntu 24.04 + Nginx 反代 80→8080 + systemd |
| 计费 | 按用量；空闲缩容到 0，**不跑不花钱** | 按实例；**不关机就持续计费** |
| 额度 | 体验版 **3000 点/月**，`EnableOverrun=false`，**耗尽即停服** | 无点数天花板 |
| 资源 | 配 1C2G | 2 核 / 1.7Gi + 2G swap（我们加的） |
| 冷启动 | MinNum=0 时约 10s | 常驻无冷启；重启秒级 |
| 高可用 | 托管探针 + 自动重启 | systemd `Restart=always` 只防进程崩，VM 宕机=全断 |
| 持久化 | 容器盘易失 | `/opt/video-agent` 落盘持久 |
| 安全 | 默认 HTTPS | 仅 80 明文，**无 TLS**（待加 certbot） |
| 上线 | CLI 提交 + 轮询 | 本地构建 UI + 传 tarball + `deploy-to-cvm.sh` |

**为什么切？** 云托管 2026-09-04 实测本周期已耗 2908.6 / 3000 点，仅剩 91.4 点——演示期外会停服。CVM 甩掉额度天花板，代价是持续计费、小内存、需自己加 HTTPS 与保活。

**小机型两个硬约束（决定了方案）**
- 1.7Gi 内存跑不动 `vite build` → **UI 本地构建**后随包上传，服务器只 `npm ci`（靠 2G swap 撑过 6 分钟装 492 包）。
- 安全组只放行 80/443、8080 未放行 → 不去改安全组，直接 Nginx 反代 80→8080，URL 更干净。

## 4. 踩坑与改进（面试可讲 P0/P1/P2）

- **P0 凭据泄漏**：`工具模型.txt` / `deploy/models.json` 含明文 key，已在 git 历史中。已加 `.gitignore` + `*.tar.gz` 忽略，但**密钥轮换需人工**。→ 讲「安全左移 + 密钥不入仓」很有素材。
- **P1 跨镜人物换人**：LLM 把中文名转写成英文（小赵→Zhao），外貌锚点匹配只认中文名 → 补 `englishName` 回填 + 英文名变体匹配。
- **P1 性别音色误派**：8/11 男角色被派女声（regex 不命中直呼姓名）。新增 `CoCharacter.gender` 显式声明优先于推导。
- **P2 SSE 被 Nginx 缓冲**：`proxy_buffering off` 才实时。
- **P2 字幕越界 / 拼接缝**：字幕 timing 抽成三层回退（词级时间戳→silencedetect→三重收束）；邻镜运镜词触发硬切降级，避免 xfade 叠拉伸缝。

## 5. 面试一句话总结集（按主题背）

- **项目本质**：「多 Agent 在团队频道里协作完成视频广告生成，核心是音频驱动管线 + ReAct 并发调度 + 多 key 限流池。」
- **为什么不用单一 LLM 直接生成**：「视频生成是长链路、多模态、强约束任务，单 LLM 无法同时满足剧本一致性、角色外貌锚定、RPM 限速、口型同步，必须用 DAG + 专业 Agent 分工 + 闸门守卫。」
- **Agent 协作怎么不失控**：「导演角色做决策中枢，团队频道做可见协作，SSE 双通道做实时状态/事件流，每阶段配守卫（D1 台词、Cross-shot 一致性、限流池）。」
- **最大的工程权衡**：「为小内存机型放弃服务器侧构建、本地构建 UI；为绕开安全组用 Nginx 反代；为甩掉云托管额度天花板自建 CVM——都是约束驱动的设计。」
- **如果重做**：「把密钥管理做成 runtime 注入而非落盘明文；CVM 升 2C4G 跑长片；加 certbot HTTPS + 自动伸缩。」

## 6. 高频追问 + 应答要点

| 追问 | 应答要点 |
|---|---|
| 多 Agent 怎么保证不互相覆盖产物？ | 版本化资产 `withVersionedAsset`：先备份再生成；失败只回滚自己刚 push 的那项；并发安全。 |
| RPM 限速怎么做的？ | 每 key 独立池，`pickPool()` 选池，`reserveShotQuota` 唯一决策点；总 RPM = 各池之和。 |
| 为什么 SSE 要双通道？ | `run` 给状态快照、`ev` 给增量团队事件；`ev` 不触发 persist，高频流必须独立字段避免全量重渲染（zustand v5 引用陷阱）。 |
| 一致性怎么保证？ | 美术 bible 外貌短语回填进 prompt + 审校模型预检 + 跨镜英文名匹配。 |
| 部署为什么从云托管切 CVM？ | 云托管体验版 3000 点额度耗尽即停服；CVM 无天花板，代价是持续计费+自运维。 |
| 成本？ | 云托管按用量（1C2G 常驻≈¥85.7/月但受 3000 点封顶）；CVM 按实例持续计费，空窗期应关机。 |
