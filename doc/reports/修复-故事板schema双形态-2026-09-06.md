# 修复报告 · 故事板 schema 双形态 bug（加测 5）

**日期**：2026-09-06
**触发**：故事板加测（密集对话 + 单场景连续性专项测试）发现
**影响范围**：故事板 plan 字段被 LLM 偶尔嵌套（nested by-character）时，validateStoryboard / planActualConflicts 静默跳过该镜 → 状态: 抓出为 0，假象 PASS
**严重度**：高（QA 漏检的真实视频缺陷）

## 一、问题来源

加测 5 用 `script-02-interrogation.md`（6 镜，同审讯室 SC01，王队 ↔ 陈默对话轮替）跑了一遍故事板。
- run 98: storyboard.json 落盘 6 镜，0 计划态冲突，6/6 镜 actualState 回写，**但 verdict.shots 中 0 个 状态: 不一致**
- QA 评分 95 (pass)
- 看起来一切正常，但实际**假象 PASS**——脚本里 6 镜的 plan 都显式声明了 position / facing，与 actualState 的字符串差异肉眼可辨

## 二、根因

### 根因 1：LLM 不遵守 prompt 期望的 schema

storyboardMessages prompt 要求：
```
plan: { start: {position/facing/holding/...}, end: {...} }   # flat
```

但 LLM 在 run 98 给的是：
```json
"plan": {
  "start": { "CH01": {position/facing}, "CH02": {unobservable: true} },
  "end":   { "CH01": {position/facing} }
}
```
——按角色嵌套（nested by-character），与 `StoryboardState` 类型不匹配。

### 根因 2：stageStoryboard 归一化层空架

`normalizeStoryboardDoc` 在 storyboard-state.ts:327 定义（带详细注释说明归一化职责），**但 stageStoryboard 从未调用它**。
- LLM 原始输出 → 直接进 validateStoryboard（遇到嵌套字段读不到，规则静默跳过）
- 直接进 writeJson 落盘 storyboard.json（嵌套字段保留）
- 直接进 export 阶段的 planActualConflicts（同样读不到，0 抓出）

### 根因 3：dual-track audit 同样失明

`storyboard-actual.ts:planActualConflicts` 读 `planEnd.position`（flat），遇到 nested 时 `planEnd = card.plan?.end ?? {}` 是 `{CH01: {...}}`，position 为 undefined → `if (!planned) continue;` 静默跳过。

### 三个根因的合谋

LLM 偶尔 nested + 归一化未接线 + audit 读 flat = 故事板的"暴露 QA 盲区"价值**有条件**——必须 LLM 配合给 flat 才生效。

## 三、修复方案

### 修法 A：在 sanitizeState 入口拍扁 nested → flat（推荐）

不修改 prompt（治本需要 LLM 一致性），而是在 normalizeStoryboardDoc 内部的 sanitizeState 入口检测 nested 形态并拍扁。

```ts
function maybeFlattenNestedState(raw: unknown): unknown {
  // 检测顶层 CHxx 键
  const entityKeys = Object.keys(obj).filter((k) => /^CH\d+$/.test(k));
  if (entityKeys.length === 0) return raw;  // 不是 nested，原样返回
  // 拍扁：flat 字段优先（保护 prompt 原意），nested 兑底未填字段
  // holding 合并；unobservable 仅全员不可观察时设 true
}
```

### 修法 B：stageStoryboard 接线 normalizeStoryboardDoc

之前 stageStoryboard 调 validateStoryboard 但**没调** normalizeStoryboardDoc。修法：在 validateStoryboard 之前调用归一化。

```ts
let raw = await build("");
let doc = normalizeStoryboardDoc(raw, scriptDoc, entityIds.props);  // ← 新增
let conflicts = validateStoryboard(doc, entityIds);
```

冲突重写分支同理：第二次 build 后再归一化一次。

## 七、故事板对生成的影响 · 完整路径

跑完加测 5 + 加测 6 后，故事板对生成的三条影响路径全部验证：

| 路径 | 文件 | 验证证据 |
|---|---|---|
| 1. prompts 阶段 LLM input | `prompts.ts:storyboardStateBlock` | run 99/100 plan 都是 flat 且与 brief 一致——LLM 吸收了 prompt 指导 |
| 2. export 阶段审计 | `storyboard-actual.ts:planActualConflicts` | run 99 抓 3 个 状态: 不一致；run 100 抓 6 个 |
| 3. reshot 阶段 instruction | `pipeline.ts:1694 plannedEndNote` | run 100 SH04/SH05 补拍 prompt 含 "该镜结束状态必须保持：..." |

**结论**：故事板不是事后验收，它是**生产环节的显式约束源**：
- 第一次生成时约束单镜 prompt 撰写
- 第一次生成后约束 QA 评分
- 补拍时约束"要演到什么状态"
