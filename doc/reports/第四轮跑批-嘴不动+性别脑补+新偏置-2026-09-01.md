## 1. 三类已发现 bug 的根因与修复

### 1.1 嘴不动问题（用户问的）— 根因 + 当前修复状态

**根因**：分镜内 visual-dialogue 动作冲突，不是分镜之间的时间线问题。

**实证**：

| 镜 | dialogue | visual | video 模型选了 | 嘴动 |
|---|---|---|---|---|
| B剧 SH01 | "坐。我们长话短说..." | 推门进来 + 放文件 | visual 动作 | ❌ |
| G剧 SH01 | "你这份简历写的什么鬼？" | 推旋转门 + 攥简历 | visual 动作 | ❌ |
| G剧 SH02 | "经理您消消气..." | 喝水 + 被呛 | visual 动作 | ❌ |
| G剧 SH03 | "坐下，听我说完" | 拍桌 + 转身背对 | visual 动作 | ❌ |
| G剧 SH04 | "我能不能再问一个问题" | 低头看鞋 | visual 动作 | ❌ |
| G剧 SH05 | "问。只给你一句话机会" | 两人静止坐着 | dialogue 动作 | ✅（dubOver=False） |

**G剧深审 confirmed 2/5**：
> "dubOver 模式未能弥补原素材嘴动缺失"

**当前修复状态**：**未修复**。这是 user 脚本设计的内在矛盾（user 需要重写脚本让 visual-dialogue 协调），不是 server bug。

**未来加固方向（未实施）**：
- runner 在 parseScript 时检测每镜 visual 是否包含嘴动友好动作（坐 / 站 / 看），如果不友好但有 dialogue，给 user 警告
- stageScript 落盘前加 visualDialogueConflict 校验

### 1.2 性别脑补 bug（关键新发现 + 已修复）

**根因**：`pi/packages/video-agent-server/src/prompts.ts:coSpaceBlock` 输出人物时只输出 `name + description`，**没注入 `gender` 字段**。

```ts
// Before
.map((c) => `- ${c.name}：${c.description}`)
// After
.map((c) => `- ${c.name}${c.gender ? `（${c.gender === "male" ? "男" : "女"}）` : ""}：${c.description}`)
```

**实证**：

| 剧本 | coSpace.characters 声明 | 修复前 design-bible | 修复后 design-bible |
|------|--------------------------|---------------------|---------------------|
| H剧 小赵 | "（男，28 岁）：社区医院护士" | "28-year-old **female** nurse" | "28-year-old **male** nurse" ✓ |

**影响范围**：所有用新格式 `（男/女，X 岁）` 且**coSpace.characters.description 不显式提及性别**的脚本都会触发。A-F 6 部因为 description 里写了"男/女"关键词绕过了；H 剧因为描述只有"护士"被脑补成女护士。

**当前修复状态**：✅ 已修复（`prompts.ts:coSpaceBlock`）。H剧重跑验证 video 也对（年轻男性护士）。

### 1.3 末时点系统性偏置（第 4 类 LLM-as-judge 偏置）— 已记录

**现象**：deep-review model 报的视频时长比实际短 4s。

**实证**：

| 剧 | 实际 final.mp4 | model 报告 |
|----|----------------|-------------|
| D剧 第三轮 | 22.67s | 18.89s |
| E剧 第三轮 | 27.87s | 23.60s |
| I剧 第四轮 | 32.16s | 27.54s |

**当前修复状态**：**未修复**。建议方案：
1. 把 `finalDurationSec` 作为 ground truth 显式告诉 model（已有），并加 prompt 规则："请基于提供的 finalDurationSec 报告，不要自行估计视频长度"
2. 在 video_url 后面追加 `{type: "text", text: "成片实际时长 X 秒"}` 文本作为冗余 ground truth

**其他发现**：LLM 视觉生成不稳定（场景有时跳到机场、互动角色错配），但这是 LLM 随机性，不是 server bug。

## 7. 一句话总结

**第四轮把"嘴不动"问题追到了三种根因：**
1. **user 脚本设计**：visual-dialogue 内在矛盾（5 镜 G剧确认 4 镜不可协调）—— user 侧
2. **server 性别注入缺失**：coSpaceBlock 没传 gender，visual LLM 自由脑补（已修复）—— server 侧
3. **video 模型跟读能力限制**：即使前两条都对，video 仍可能生成乱语嘴型（MEMORY §3.1）—— 不可控

**最实用修复**：① coSpaceBlock 加 gender（已做）；② user 修脚本让 visual-dialogue 协调；③ deep-review prompt 持续加 ground truth 防御 4 类偏置。
