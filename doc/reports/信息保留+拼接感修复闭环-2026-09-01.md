## 1. Fix 1 — 关键信息中途丢失（user 脚本逐镜意图）

### 1.1 根因

user 脚本 `.md` 详细到逐镜 dialogue / visual / audioMode / characterId，但 runner 只把 `logline` + `shotCount` 传给 `/api/generate` API。Server 端编剧阶段（stageScript）拿不到 user 的逐镜意图，LLM director 自由发挥——典型症状：

- **B 剧 SH06**：user 设计是 `audioMode: dialogue`，陈默台词"那是因为……我正在写一本悬疑小说。" → LLM director 改成 `audioMode: narration`，旁白"真相，藏不住。" → 成片字幕里 SH06 出现的是旁白不是陈默台词
- **跑批反馈**（第一轮）：发现配音性别问题、C剧 60→3 评分震荡等，多半是因为 LLM 重写 user 设计
- **deep-review 幻觉**：B剧 "智能审讯系统平板画面"是 deep-review 编的（user 脚本里只有"陈默低头阴影"）

### 1.2 修复

**新字段 `coSpace.scriptIntent`** —— user 逐镜剧本意图，作为共创空间的可选字段。Server 编剧阶段检测到时**跳过 LLM 编剧**直接采用，仍走 `normalizeScript` + D1 闸门 + A7 音色绑定 + 单 speaker 守卫，保证下游阶段拿到合法 `ScriptDoc`。

### 1.3 改动清单

| 文件 | 改动 |
|------|------|
| `pi/packages/video-agent/src/clarify/types.ts` | `CoCreationSpace.scriptIntent?: { title?, logline?, shots: [...] }` |
| `pi/packages/video-agent-server/src/server.ts` | `coSpaceFromBody` 解析 scriptIntent（宽容：非法字段丢，缺字段透传） |
| `pi/packages/video-agent-server/src/stages/script.ts` | 检测 `run.brief.coSpace?.scriptIntent` → 跳过 LLM 编剧 + normalize + D1 + A7 + setStage("done") |
| `doc/scripts/dense-dialogues/run-scripts-v2.mjs` | runner 解析 `## 人物` 段 + 逐镜 `dialogue / characterId / visual` → scriptIntent |
| `doc/scripts/dense-dialogues/run-single.mjs` | 单脚本跑批（用于验证单部 fix） |

### 1.4 验证

**B剧 SH06 修复实证**：
- Before（第一轮跑批）：成片字幕 SH06 是"真相，藏不住。"（旁白，audioMode=narration）
- After（脚本意图注入后）：成片字幕 SH06 是"那是因为……我正在写一本悬疑小说。"（dialogue, char=陈默）

**事件触发**：
```
用户提供了 scriptIntent，跳过 LLM 编剧，采用 6 镜用户剧本（补遗 §4 根治点）。
```

### 1.5 软约束 vs 硬约束

本 fix 是**半硬约束**：user 提供 scriptIntent → server 完全跳过 LLM 编剧。但 `visual` 字段在下游 stages（keyframe prompt、clip prompt）仍由 LLM 补全细节——这是有意保留的弹性，因为 user 写的画面描述通常较粗，LLM 细化能改善质量。

**未来加固方向**：
- `coSpace.visualIntent`: 像 scriptIntent 一样作为 user 提供的逐镜 visual，server 在 prompts 阶段也跳过 LLM
- 但当前 visual 质量不够稳定（user 通常写 30 字粗描述），过早硬约束可能反而拖累效果

## 2. Fix 2 — 转镜 + 镜头拉伸的拼接感

### 2.1 根因

EDL 阶段由 LLM 决定转场（cut/fade/dip/white/wipeleft/slideup），clip prompt 又要求运镜（"写明具体镜头运动：dolly push-in / pan left / handheld follow / static locked-off 等"）。当 LLM 选 `fade/dip/white/wipeleft/slideup` 且邻镜 clip prompt 含 zoom/dolly/push-in/handheld/tilt 等运镜词时：

- xfade 让 source 末尾帧和 target 开头帧**叠在一起**
- 两帧都在做运镜（推/拉/摇）
- 运镜在画面上叠加 → **肉眼可见的拼接缝**（画面像被撕开）

**问题实证**：B剧 LLM 选的 transitions.json 之前是 `white/impact`（SH04→SH05）和 `dip/whoosh`（SH05→SH06），而 SH05/SH06 的 clip prompt 都有 `handheld+tilt` 和 `dolly+push-in`。

### 2.2 修复

**两层防护**：

1. **EDL prompt 加规则**（规则 5/6）：
   > 5. 拼接安全：邻镜 visual 含 zoom / dolly / push-in / pull-back / tracking / pan / tilt / handheld / crane / steadicam / follow 等运镜词时，**必须用 cut**——xfade 与镜头拉伸同存会让运镜在画面上叠加，产生明显拼接缝；
   > 6. 镜头运动的镜头之间不要用 fade / dip / wipe / slide（任何叠化/擦除/滑动都会与运动叠加）；

2. **服务端兜底**（EDL prompt 之后 + 落盘之前）：
   - 读 `prompts.json`（实际发给视频模型的 prompt）查每镜运镜词
   - 邻镜任一含运镜词 + transition ≠ cut → 强制 type="cut" + durationSec=0 + sfxType=null
   - 同时清空 cut 上残留的 sfx（防止 LLM 乱输出）
   - 触发时 pushEvent 留痕

| `pi/packages/video-agent-server/src/stages/export.ts` | 加载 `prompts.json` + 邻镜运镜检测 + 强制 cut + sfx 清空 + 触发事件 |

## 5. 经验沉淀（建议纳入 MEMORY.md）

1. **user-intent 通路必须 schema 化** — 当 LLM 是中间环节时，user 的精细设计必须以 schema 字段显式传递；依赖 prompt 软约束（"优先采纳"）不够稳
2. **跨阶段决策要校验"邻近环节的副作用"** — EDL 决定转场时不知道 clip prompt 会有运镜，必须有跨字段校验；这种 cross-stage 校验应该是数据流架构的常态
3. **服务端兜底永远比 prompt 约束更可靠** — EDL prompt 加规则 5 是软约束，LLM 可能漏判；服务端 hasCameraMotion 是硬约束；两道一起上
4. **video generation 的 prompt 才是 ground truth，不是 script.json visual** — scriptDoc.shots[].visual 是 user/脚本级描述；prompts.json 才是真正发给视频模型的字段；跨字段决策要以后者为准
