# 更正报告 · "对话跑批全部误判"（加测 8 揭示）

**日期**：2026-09-06
**触发**：用户反馈"台词还是经常对不上，或者有字幕却没声音"
**影响**：之前所有"dialogue 模式下的故事板表现"判断都是错的——实际跑的是旁白模式

## 一、问题来源

用户提出"台词对不上/有字幕没声音"问题后，我开始排查字幕声音对齐链路。在 `curl http://127.0.0.1:8790/api/runs/run-mtpo7zvk-99` 查询 options.audioDrive 时发现：

```json
{
  "resolution": "720p",
  "audioDrive": "off"   ← 真真相
}
```

但我之前明明在 probe 里设了 `audioDrive: "dialogue"`。再看 script.json 的 audioMode 分布：6/6 都是 `narration`（被 A1 闸门降级）。

## 二、根因

### 根因 1：Server API 字段名不一致

server.ts:588 写的是：
```ts
const options = resolveGenerationOptions(req.body?.options ?? undefined);
```

但 probe 用的是 `req.body.generationOptions`。字段名不一致 → server 端读到 undefined → resolveGenerationOptions(undefined) 走默认 → audioDrive = "off"。

### 根因 2：A1 闸门设计兜底

server.ts:953 (pipeline.ts):
```ts
const audioDriveGated = shouldGateAudioDrive(options.audioDrive, input.coSpace);
if (audioDriveGated) options.audioDrive = "off";
```

`shouldGateAudioDrive(audioDrive="off", coSpace=...)` → false（因为 audioDrive 不是 "dialogue"）。但 audioDrive 已经是 "off"，闭门也没用。

### 根因 3：probe 没做服务端字段验证

之前的 probe 直接发请求，没验证 server 收到的 audioDrive 实际是什么。端到端测试缺失。

## 五、用户问题的真实答案

用户提的"台词对不上/有字幕没声音"在 **真实 dialogue 模式下应该很少出现**（dubOver 100% 触发，TTS 同源对齐）。之前我误以为是 dialogue 跑了几个批次的"故事板效果"，但那些是 narration 模式，**根本与 dialogue 路径无关**。

但用户说"经常对不上"是有理由的。可能原因：

1. **参考成功路径少**：在真实 dialogue 模式下，agnes reference 100% 失败 → 100% dubOver。如果偶尔 reference 成功时，agnes 生成的音频长度可能与 TTS 不同（差 1-2 秒），subtitle 用 TTS wordTimestamps 会错位。
2. **storyboard.json 缺失**（run 108 这次就超时了）：subtitle 退到 silencedetect 或 fallback，可能与 TTS 实际起止错位。
3. **narration fallback 路径**：如果 reference 提交失败（不是 reference 跟读失败），audioMode 降为 narration，台词回填到 narrationZh，stageAudio 重新生成旁白 TTS。subtitle timing 走 silencedetect 旁白 TTS——理论上对齐，但实际是否真对齐需要测。
4. **dubber 路径下音频长度对不上**：如果 TTS rawDurationSec 与最终 dubOver 用的 TTS 文件时长不一致（pad 插停顿版本可能不同），会出现"字幕早结束 / 声音晚结束"。

## 六、修复

### 修法 1：server.ts 兼容两个字段名

```ts
// server.ts:588, 613
const options = resolveGenerationOptions(req.body?.options ?? req.body?.generationOptions ?? undefined);
```

### 修法 2：单测覆盖

`test/api-audio-drive.test.ts`：4 个测试锁定 audioDrive 行为：
- `audioDrive: 'dialogue'` + 完整 options → 保留
- `audioDrive: 'dialogue'` + 极简 options → 保留（其他字段走默认）
- audioDrive 缺失 → 默认 'off'
- audioDrive 非法值 → 默认 'off'（白名单过滤）

### 修法 3：probe 端到端验证

新增 probe 必须验证 `GET /api/runs/:id → options.audioDrive == "dialogue"` 后才开始跑批。
