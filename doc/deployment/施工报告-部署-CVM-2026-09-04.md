## 2. 机型约束与方案选择（本次最关键的一个决策）

探查结果：2 核 / **1.7Gi 内存** / 有 docker、git、curl / **无 node、无 ffmpeg** / sudo 免密。

| 方案 | 判断 |
|---|---|
| 服务器上 `npm ci` + `vite build` | ❌ vite 构建 UI 峰值内存超 1G，必 OOM |
| Docker 构建镜像 | ❌ 同样要在机内跑 npm ci + vite build，且 dockerd 本身再占 70MB |
| **本地构建 UI + 服务器只装依赖** | ✅ **采用** |
| 上传 392M node_modules | ❌ 体积大且跨平台二进制不通用，不如服务器 npm ci |

**最终方案**：
1. 本地 `vite build` 出 UI dist；
2. 打包 `pi/`（排除 node_modules/dist）后**单独补** 5 个 workspace dist + UI dist + `deploy/models.json` → **6.6M** tar.gz；
3. 服务器跑 `deploy/deploy-to-cvm.sh`：2G swap → apt ffmpeg → NodeSource Node 22 → npm 源切 npmmirror → `npm ci` → systemd。

## 3. 踩到的坑（按严重度）

| # | 坑 | 现象 | 解法 |
|---|---|---|---|
| 1 | **1G 内存跑 vite build** | 必 OOM | UI 在本地构建，服务器只 npm ci（配 2G swap + `NODE_OPTIONS=--max-old-space-size=1024`） |
| 2 | **8080 安全组未放行** | 服务本地全绿，公网 curl 超时 | 改用 **80 端口 Nginx 反代**（80/443 已放行，实测 TCP 通但无监听） |
| 3 | **nginx 装完就自启动，跑的是默认配置** | 我替换了 sites-enabled 却仍返回 "Welcome to nginx!" | 改配置后必须 `systemctl restart nginx`（`enable --now` 对已 active 的服务不会重载） |
| 4 | **paramiko 后台执行超时** | `stdout.read()` 等不到 EOF → `PipeTimeout` | 后台跑必须 `setsid ... </dev/null >log 2>&1 &`，或干脆不 read 直接 sleep |
| 5 | 本机无 sshpass | 无法非交互传密码 | 隔离 venv 装 paramiko（`~/.workbuddy/binaries/python/envs/default`） |
| 6 | `/api/generate` 报 400 | 我按 `logline` 顶层传参 | 实际要 `{ brief: { logline } }`（`briefFromBody`） |
| 7 | SSE 被 Nginx 缓冲 | 事件流攒住不推（预判规避） | `proxy_buffering off` + `Connection "upgrade"` + `proxy_read_timeout 3600s` |
