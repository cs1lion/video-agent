# 2026-08-29

## 意图识别 + 澄清提问 + 轨迹回放 + RLHF 框架设计（16:00，报告：video-agent_意图澄清与RLHF轨迹框架设计.html）

用户想在 video-agent 加入意图识别、澄清式提问策略、保留轨迹回放并用于 RLHF，要一个功能框架。
做法：**先源码实读做家底盘点，再给增量设计**——结果发现 80% 的组件已存在，答案是"补一层"而非"从零建"。

### 家底盘点（源码实读，重要，别重复探索）

- **创作意图**：`IntentKey` 15 维（primaryEmotion/visualStyle/subjectFocus/lighting/pacing/
  colorPalette/music/narratorVoice/cameraLanguage/storyArc/referenceEnergy/onScreenText/
  ctaStrength/handModel/soundDesign）　`clarify/types.ts:25`
- **动作意图**：`DirectorIntent = none|reshot|retts|reexport`，`planDirectorReply()` LLM 解析　`pipeline.ts:1900/:1910`
- **澄清提问**：10 条固定题（core/refinement 权重）+ 5 条 LLM 定制题，选项带 `promptTags`
  注入下游；`interviewLog: InterviewLogEntry[]` 已是澄清轨迹雏形　`clarify/questions.ts`、`types.ts:98`
- **执行轨迹**：`TraceSpan` 落盘 `traces.ndjson`（"Run 即 Trace"）　`pipeline.ts:158/:718/:1840`
- **偏好信号**：审议每轮 `proposals[]` + 采纳回写 `adopted`（`markAdopted`）　`deliberation.ts:141/:890`
- **质量分**：`QaVerdict{overall, score, axes[], shots[]}` 多轴　`pipeline.ts:149`、`qa/review.ts:77`
- **缺失**：轨迹回放（无）、RLHF 管线（无）、决策记录（无）

### 核心诊断（最有价值的判断）

**有执行轨迹，没有决策轨迹。** RLHF 要 `(state, action, reward)`：
- state：素材有但没按决策点做快照
- action：**缺口最大**——TraceSpan 只记执行结果（调了什么/耗时/成败），不记候选集与选择
- reward：素材充足（QA 轴分 / 采纳 / 重做次数 / 是否交付），但散落

**关键推论**：只记 chosenAction 不记候选集 → 只能做 SFT，做不了偏好学习。
而审议模块**天然产出候选集**（每轮 3-5 个 proposals），只要把"候选集 + 采纳项"结构化，
就直接得到偏好对，**无需额外标注**。

### 增量设计

- **三层轨迹模型**：L1 Execution Trace（已有 traces.ndjson）+ L2 Decision Trace
  （新增 decisions.ndjson）+ L3 Preference Event（新增 preferences.ndjson），
  用 episodeId + decisionId 串联成 Episode。
- **DecisionSpan 关键字段**：state 快照 / **candidates[]（不能省，这是 rejected 侧）** /
  chosenId / rationale / confidence / spanIds。
- **埋点最小侵入**：新增 `appendDecision()` 对称于 `appendSpan()`，只在 4 个决策点旁路写入
  （planDirectorReply、clarifier 选题、审议提案、调度 submit），**不改现有行为**。
- **意图增强**：加 confidence + ambiguity（低置信时反问而非瞎猜，避免误判白烧一次重做）；
  DirectorIntent 从 4 类扩到 7 类（+inquire/modify/abort）；加 intentHistory。
- **澄清增强**：信息增益驱动选题（impact × uncertainty）、logline 预推高置信维度只确认、
  收益阈值停止、记录 skipped。impact 初始人工标注，别一上来就学。

### 额外发现（本轮最高价值）

**澄清答案被后续导演指令推翻 = 最强负样本。**
例：访谈选了 pacing=fast，成片后说"节奏太拖" → 该维度澄清失效。
比"采纳了哪个提案"信息量更高（负样本稀有且精准指出哪个维度失效）。
采集：比对 intentHistory 同维度前后值 / 检测否定式指令与已存意图冲突。
用途：① 短期优化题库表述（人工看报表）② 中期训 logline→意图默认值 ③ 长期作 DPO rejected 侧。

### 落地五阶段（刻意不跳步）

① 数据结构 + 旁路埋点 → ② 补齐候选集记录 → ③ 只读回放 UI（时间线重建）
→ ④ **离线分析报表（不训练就有收益，性价比最高，常被跳过）** → ⑤ 数据导出与训练

**冷启动门槛**：阶段②≥50 episode；RM ≥300 带分样本；DPO ≥1000 偏好对。
数据不足是最大现实约束，别一上来就 DPO。

### 风险

候选集质量（若审议只出 1 个提案则无 rejected 侧 → 提案 prompt 应要求 3-5 个差异化候选）；
确定性重放不可靠（视频模型 seed 语义未承诺，只承诺"输入可重建"）；
分布漂移（样本带 schemaVersion/modelVersion）；脱敏（导出物不进仓库）。
