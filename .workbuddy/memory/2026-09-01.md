## 16:16 查证「CloudBase 能否查访客」+ 修正上轮错误结论

- **结论：CloudBase 云托管查不了访客，只能查请求量。** 官方监控指标只有
  调用次数 / 响应时间 / QPS / HTTP 错误(404,500) / CPU / 内存 / 实例数，
  **没有 IP、UV、来源、UA、地域**（统计的是请求数不是访客数）。
  云托管的「用户管理」只统计接入 CloudBase Auth 的登录用户，本项目没接 Auth，不适用。
- 实测 `getProcessLog` 只返回部署步骤 2 行，**无任何访问记录**——服务端未装访问日志
  中间件（morgan/pino 均无），stdout 里没有请求日志。可用路径：① 前端插统计脚本（最省）；
  ② 服务端加 access log 中间件 → stdout → CLS（可检索，CLS 独立计费且绑定后不可切回）。
- **修正上轮错误**：说「传值与现配置一致即可避免重部署」不成立——实测传
  `{MinNum:1,Cpu:1,Mem:2,Port:8080}` 仍产生 **009** 部署记录（BuildId=0，复用 008 镜像、
  不重新构建、~30s、服务未中断）。最干净做法：`serverConfig` 只传 `{MinNum:n}`。
  已改 deploy/README.md + 坑位速查 + MEMORY（commit b6f6bdc）。
