### 2. 部署到腾讯云 CVM 49.233.207.18（Ubuntu 24.04 / 2核 / 1.7Gi / 50G）

已上线：**http://49.233.207.18/**（公网可访问，端到端冒烟通过）

关键决策与坑（详见 `doc/deployment/施工报告-部署-CVM-2026-09-04.md`）：

1. **1.7Gi 内存跑不了 vite build** → 定案「本地构建 UI + 服务器只 npm ci」，
   服务器再配 2G swap + `NODE_OPTIONS=--max-old-space-size=1024`。
2. **8080 安全组未放行，80/443 已放行**（80 返回 "Empty reply" = TCP 通但无监听）
   → 不申请开安全组，改用 **Nginx 反代 80 → 8080**，URL 更干净。
3. **apt 装完 nginx 会自动启动并跑默认配置** → 替换 sites-enabled 后必须
   `systemctl restart nginx`（`enable --now` 对已 active 的服务不重载）。
4. SSE 必须 `proxy_buffering off` + `Connection "upgrade"` + `proxy_read_timeout 3600s`，
   否则团队频道事件流被 Nginx 攒住不推（已实测公网 SSE 实时到达）。
5. 本机无 sshpass → 隔离 venv 装 paramiko。paramiko 后台跑任务需 `setsid ... </dev/null >log 2>&1 &`，
   否则 `stdout.read()` 等 EOF 超时。
6. `/api/generate` 请求体是 `{ brief: { logline } }`，不是顶层 `logline`。

验证结果：`/api/health` 200；`/` 200（标题 Video Agent — 视频广告工作台）；`/api/` 404；
端到端跑批（3 镜）剧本阶段正常，SSE 双通道 `event: run` / `event: ev` / `: ping` 全通，取消正常。
