## 视频「音频驱动口型」可行性实测（报告：视频音频驱动验证报告.html）
用户想改 video-agent 逻辑：剧本→TTS→把语音交视频模型辅助生成（角色台词视频）。实测结论：
- TTS：StepFun `/v1/audio/speech` 返回二进制 MP3，不给 URL，需自托管。
- 媒体URL公开访问：CloudBase 存储可得永久匿名可访问 URL（206/audio/mpeg），满足 Agnes「任务完成前保持有效」要求 ✅。
- 国际站 `agnes-video-v2.0`（当前 Key 仅此站有效）：`audio`/`image` 参考参数静默忽略（非法 URL 也 200，口型与参考音频相关系数 −0.056）；但原生音画同生，把台词写进 prompt 会自动生成人声并对口型（中英文实测：中文台词 5s 内 68% 时长有声）。
- 中国站 `agnes-video-2.5` 文档有 `audios` 参考模式，但当前 Key 在 api.agnes-ai.cn 401「无效的令牌」。
- **重大修正（用户要求用 2.5-flash 重试）：国际站 apihub.agnes-ai.com 其实也有 `agnes-video-2.5-flash` / `agnes-video-2.5`，且当前 Key 可用**——之前只测了 v2.0 导致误判「音频被忽略」。
- **2.5-flash 真正 honors `audios` 参考**：①蜂鸣参考(440Hz)→输出频谱 440Hz 占 63.4%（原音频直通）；②中文语音参考→输出音轨包络与参考相关系数 **0.620**、逐秒吻合。说明按你的语音对口型且直接用该声轨。v2.0 才是静默忽略音频的那个（corr −0.056）。
- **结论翻转**：用户的「剧本→TTS→喂视频对口型」链路成立 ✅。落地架构：StepFun TTS(按角色选voice)→CloudBase 公开URL→2.5-flash mode=reference audios=[URL]。注意：生成限流 2次/分钟；状态查询用 `GET /v1/videos/{id}`（非 v2.0 的 agnesapi）。

## 视频生成并发调度的 ReAct 代理设计（18:10，报告：视频生成调度ReAct代理设计.html）

用户提出：多 key 不是同质扩容，而是几个「能力/配额/成熟度不同」的烤炉，
应由 agent（导演或新角色）用 ReAct 做并发调度。评估后判定**思路成立且优于静态队列**，
产出完整设计报告。核心决策：

- **静态队列失效的根因是异构性**，不是限速：TokenPlan 有 500s/天硬配额、Enterprise/Free
  只有 RPM 无时长配额；5s/10s 片段成熟度不同 → 队头阻塞；任务有上游依赖；
  **失败重试同样按秒烧配额**。这是资源分配优化问题，不是速率限制问题。
- **三层职责边界（不可妥协）**：L3 策略层=ReAct 代理（投哪个任务到哪个炉/何时投/
  是否降级放弃）；L2 守卫层=确定性代码校验 RPM 令牌/剩余配额/依赖，**违规则否决退回**；
  L1 执行层=HTTP + 429 退避 + webhook + 幂等。原则：**代理有建议权，代码有否决权**。
  （LLM 会幻觉出不存在的 ovenId 或超配额决策，违规代价=真烧配额+429 惩罚）
- **角色分工**：调度不给导演（会被资源噪声淹没创意判断），新设**「制片主任」ReAct 代理**；
  导演负责下 `{clipId, priority, qualityBar, mustKeep}` 优先级契约，
  制片主任反向通报 `budget_alert`。创意决策与资源决策解耦为两个 agent + 结构化契约。
- **Oven 模型**：id/keyType/rpmCap/tokens/dailyQuotaSec/remainingQuotaSec/inFlight/etaSec。
  关键洞察：**RPM 只卡提交频率，已提交任务在后台并行出片**——投料受限但炉内可多烤。
- **成本与稳定**：事件驱动（任务就绪/炉空出/失败/配额跨阈值）+ 批量决策 + 5s 最小间隔
  + 决策冷却去重（防抖动）；LLM 不可用则**降级回确定性 FIFO+令牌桶**，产线不停。
- **度量**：配额利用率（有效成片秒/消耗配额秒）、P0 延迟 P95、配额浪费率、
  **决策被拒率**（反映代理是否瞎指挥，需常驻监控）。
- **诚实边界**：收益随异构性/稀缺性增长，同质 key+配额充足时静态队列更划算；
  且**加代理前建议先补 reshot/一致性缓存的回归测试**（当前无锁）。

**这是 defense-in-depth 在 agent 架构的落点**：决策层（agent）与约束执行层（guardrail）分离，
对应郭煜在研究的「执行层与数据层分离」模式。可作为 Agent 岗面试的核心架构叙事。

## 音频驱动视频改造细化（19:40，报告：音频驱动视频改造设计.html）

用户追问：音频作为驱动角色后要求更严、旁白是否删除、台词模式在共创工作室限定开放、

- 台词模式「更严格」的实质化：每角色绑定 voice / 情绪气口结构化 / **静音段是表演的一部分**
  （停顿=闭嘴）/ 每镜一条主语音 / 时长须 ≤ 镜长。
